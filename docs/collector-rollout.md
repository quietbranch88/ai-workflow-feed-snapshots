# Collector source and release procedure

The MCP repository is the sole collector code source. This repository owns the schedule and `data` branch; its checkout retains only this repository's GitHub token for writing that branch. The collector is checked out separately from the fixed public repository and full, reviewed commit SHA in the workflow, without persisted checkout credentials. Never derive the repository, revision, commands, or executable scripts from article data. The collector must treat fetched articles as untrusted data; individual source failures must remain visible in its result.

Pin the exact reviewed and published MCP commit containing the collector script and lockfile. Deploy a reader compatible with both the current snapshot and the new writer before switching the pinned revision. A mismatch between writer and deployed reader can make the public snapshot unavailable. The candidate pinned revision is `74b184bd74a4beda28deef621ccc71b81489cb8f`; the compatible reader was deployed and read the existing unversioned snapshot on 2026-10-31.

To test a candidate without changing the scheduled default branch, commit the workflow with the reviewed SHA on a separate branch in this repository, then invoke `workflow_dispatch` with that branch as the ref. The job still pushes its output to this repository's `data` branch; the test therefore updates the public snapshot and requires an authorized test window. Check the run conclusion, read back source statuses and timestamps from `data/snapshot.json`, and query the actual MCP endpoint. A manually dispatched run does not prove the daily schedule has executed. Leave the scheduled default branch unchanged until the reviewed release is approved.
